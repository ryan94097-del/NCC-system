### 2026-07-04 — 放棄「舊 Python + Streamlit」方向，重建為純前端 HTML

- **背景**：先前用其他 AI 工具做的 Python/Streamlit 版本（`app.py`）成效差：DuckDuckGo 對台灣電商索引極差、MOMO 被判定無法爬、Yahoo regex 解析脆弱。
- **決策**：整個重建。
- **狀態**：舊 `app.py` / `test_search.py` 已廢棄，不納入 repo。

### 2026-07-04 — 確定交付物為「純前端單一 HTML 檔」

- **背景**：使用者最終釐清：工具只能在**公司鎖定電腦**上使用，該環境**不能用 Python、網路受鎖定、禁裝軟體**。
- **評估過的方案與否決理由**：
  - Streamlit 本機 App → 需 Python，否決。
  - PyInstaller 打包 `.exe` → 鎖定電腦會擋未簽章執行檔，否決。
  - Vercel / 雲端 Serverless → Playwright 跑不動、資料中心 IP 被電商擋、且非免費，否決。
  - 「在家用電腦跑搜尋、公司只看報告」的雙機方案 → 使用者要求全部在公司電腦完成，否決。
- **決策**：**純前端單一 HTML 檔**，內嵌 SheetJS，零安裝、離線可用。

### 2026-07-04 — 接受「無法自動爬蟲/截圖/抓價」的現實

- **理由**：瀏覽器 CORS + 無後端 + 鎖定網路，物理上無法自動抓取電商資料。
- **決策**：改為「一鍵搜尋連結 + 人工核對 + 手動填價/貼截圖」的工作表模式。工具定位 = 智慧待查清單 + 搜尋啟動器 + 核對紀錄表。

### 2026-07-04 — 賣場範圍

- **納入**：MOMO、Yahoo 購物、Google 購物/搜尋、露天、酷澎(Coupang)、蝦皮。
- **排除**：PChome（使用者要求）。

### 2026-07-04 — 新增「共用密碼」登入機制（AES 加密）

- **背景**：工具會分享給同事,需要一道使用門檻。
- **技術現實**：純 HTML 無後端,無法做真正的帳號驗證(輸入端可讀原始碼繞過)。「分辨每個使用者/記錄操作」需後端,鎖定環境做不到,已否決。
- **決策**：採用**單一共用密碼 + Web Crypto AES-GCM 全內容加密**——工具本體以密文存放,輸對密碼(PBKDF2 派生金鑰)才解得開,沒密碼拿到檔案也無用。瀏覽器內建 API,無需 CDN/後端,離線可用。
- **限制**:單一共用密碼,無法分辨個人;換密碼需重新產生檔案。
- **附帶**:提供一支同為純 HTML 的「打包/加密器」(`builder.html`),讓使用者可在瀏覽器內更新工具內容或換密碼、重新產出加密檔,全程免 Python。

### 2026-07-04 — v1.1：隨機抽樣 + 賣場 NCC ID/型號比對

- **背景/規則**：使用者澄清核對規則為「賣場頁要有 NCC ID → 與清單對齊 → 再比型號一致」；並要 LPD/TTE 各自設定抽樣筆數、可隨機抽選。
- **決策（已實作於純 HTML）**：
  - 抽樣：LPD/TTE 各自筆數 + 隨機抽選 + 🎲 重抽；抽選穩定（編輯不reshuffle）。
  - 比對：每列新增「賣場 NCC ID」「賣場型號」欄；以全清單證號索引自動判定。**ID 比對標準＝存在清單任一筆即相符**（並標註是否對到其他筆）；**型號自動比對**（寬鬆：僅比英數、忽略大小寫/符號）。結論徽章：✅相符 / ⚠️型號不符 / 🔵待填型號 / ❌不在清單 / ⛔未填。
  - 匯出（CSV/Excel/HTML）皆含賣場ID、賣場型號、比對結論、對應清單型號。
- **關於後端**：評估 Firebase / Streamlit Cloud / 免安裝 exe。結論：自動讀取賣場 NCC ID 受反爬蟲+圖片內文字所限，換後端也不可靠；雲端方案還可能被公司網路/資料政策擋。使用者選擇**維持純 HTML** 先加功能。細節見對話。

### 2026-07-04 — v2：Streamlit Cloud 版（真正自動比對 Yahoo/MOMO）

- **背景**：使用者要「自動比對賣場 NCC ID + 確認型號 + 給連結 + 隨機抽樣湊筆數，湊不滿自動找下一筆」。
- **可行性實測（關鍵）**：
  - **Yahoo購物**：搜尋頁 HTML 內含結構化 `NCC認證碼_XXX` + `型號_XXX`（80 商品 73 有配對）→ 一次請求即可自動比對。🟢
  - **MOMO**：搜尋頁無 ID，但**商品詳細頁**原始 HTML 含 `NCC字號：CCAN...`（結構化 spec）→ 搜尋取 i_code 再逐頁抓。🟢（較慢、請求量大）
  - **酷澎** 403 擋、**蝦皮** API 無文字、**Google** 聚合無 ID、從伺服器爬 Google 會被驗證碼擋。🔴
  - 實測 verify 管線：TP-Link Deco BE22→Yahoo 精確符合；Roborock Qrevo C Pro→MOMO 精確符合；fill-to-count（假貨自動跳過、真貨補齊）通過。
- **決策**：新增 `streamlit_app/`（app.py/ncc_core.py/scrapers.py/verify.py/requirements.txt），部署到 Streamlit Community Cloud（免費）。確認標準＝**ID 在清單 + 型號一致**（使用者選）。共用密碼以 `st.secrets["app_password"]`（預設 ncc2026）。
- **前提/限制**：需公司放行 `*.streamlit.app` 且資料政策允許上傳；靠賣場不改版/不封鎖；MOMO 較慢有被封風險（以嘗試上限/延遲控制）。
- **與純 HTML 版並存**：HTML 版仍是鎖定環境的保底方案，兩者共用解析/比對規則。

### 2026-07-25 — v3 Streamlit 版重寫：CCAN 雙池抽樣 + 多層搜尋 + 深色 UI

- **背景**：原 v2 搜尋效果不佳（僅單一關鍵字策略）、缺少 CCAN/其他 RCB 分池抽樣、UI 為 Streamlit 預設樣式。
- **改進內容**：
  1. **CCAN 雙池抽樣**：依 NCC ID 第 3-4 碼（RCB 代碼）分為 CCAN（AN）和其他 RCB 兩池，LP/TTE 各 2 池共 4 組獨立配額。
  2. **多層搜尋策略**：第 1 輪品牌+型號 → 第 2 輪補強產品類別中文詞 → 第 3 輪 NCC ID 直搜，大幅提高命中率。
  3. **新增露天拍賣爬蟲**：解析頁面內嵌 JSON 或 HTML，從標題提取 NCC ID。
  4. **改進 MOMO/Yahoo 爬蟲**：增加 retry 機制、提取價格欄位、更完整的 NCC ID 匹配。
  5. **深色科技風 UI**：自訂 CSS（漸層標題、玻璃擬態卡片、漸層按鈕）、Streamlit config.toml 深色主題。
  6. **結果增強**：新增池別、搜尋輪次、可開發票、價格欄位；結果表格含 tabs（全部/已找到/未找到）。
  7. **雙格式匯出**：CSV + Excel。
- **決策**：直接取代原 `streamlit_app/` 所有檔案。維持密碼機制（ncc2026）、Streamlit Cloud 部署方式不變。
- **測試結果**：Excel 解析通過（11 筆樣本，LPD=7/TTE=4）、分池正確（CCAN/OTHER）、核心函式全部驗證通過。
