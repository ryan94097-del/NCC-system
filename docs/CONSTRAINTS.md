# 專案硬性限制（CONSTRAINTS）

> 這些是**不可協商**的環境限制，決定了整個技術架構。任何方案都必須通過這裡的檢查。

## 使用環境

工具最終在**公司鎖定的電腦**上使用，該環境有以下限制：

| 限制 | 影響 |
|---|---|
| 電腦禁止安裝軟體、**不能用 Python** | 不能用 Streamlit、不能跑 `.py`、不能打包 `.exe`（AppLocker/SmartScreen 會擋未簽章執行檔） |
| **網路受鎖定/監控** | 不能大量連向購物網站爬蟲；可能擋外部 CDN |
| 只能用瀏覽器（Edge/Chrome） | 交付物必須是瀏覽器直接開的檔案 |

## 由限制推導出的架構結論

1. **唯一可行 = 純前端單一 `.html` 檔**，內嵌所有 JS/CSS/函式庫，雙擊即開、離線可用。
2. **函式庫必須內嵌**（例如 Excel 解析用的 SheetJS 直接貼進 `<script>`），不可 `<script src="https://cdn...">`。
3. **無法做自動化的三件事**（瀏覽器同源政策 CORS + 無後端 + 鎖定網路）：
   - ❌ 自動抓商品價格
   - ❌ 自動商品截圖
   - ❌ 自動判斷是否上架
   → 全部改為「產生一鍵搜尋連結，使用者點開人眼判斷，手動記錄」。

## 工具的正確定位

不是「自動爬蟲系統」，而是：
**智慧待查清單 + 一鍵多賣場搜尋啟動器 + 核對紀錄／證據彙整表**。
它把「手動一筆筆複製型號、切換六個網站貼上搜尋」的苦工自動化，並把核對結果整理成可匯出的報告。
